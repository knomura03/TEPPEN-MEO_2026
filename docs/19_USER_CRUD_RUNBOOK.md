# ユーザーCRUD運用手順書（ADMIN / SUPERVISOR / MANAGER / USER）

最終更新: 2026-02-13

## 1. この手順書の目的
- ユーザーの作成・編集・削除を、権限ごとに迷わず実行するための運用手順です。
- 招待メールが届かない場合でも止まらないように、`招待URLコピー` / `再設定URLコピー` の代替導線を含みます。

## 2. ロールごとの操作範囲
| 操作 | ADMIN | SUPERVISOR | MANAGER | USER |
|---|---:|---:|---:|---:|
| ユーザー一覧を見る | ✅ | ✅（顧客のみ） | ✅（USERのみ） | ❌ |
| 新規作成（招待） | ✅（全ロール） | ✅（MANAGER/USER） | ✅（USERのみ） | ❌ |
| 招待URLコピー | ✅ | ✅ | ✅（USERのみ） | ❌ |
| ユーザー編集 | ✅ | ✅（顧客のみ） | ✅（USERのみ） | ❌ |
| 組織から外す | ✅ | ✅（顧客のみ） | ✅（USERのみ） | ❌ |
| 完全削除（Auth削除） | ✅ | ❌ | ❌ | ❌ |

## 3. 新規ユーザー招待（基本）
1. `ユーザー管理` 画面で `新規ユーザー作成` を押します。  
2. `名前 / メール / ロール` を入力します。  
3. USER作成時は必要に応じて店舗を選択します。  
4. 次のどちらかを実行します。  
   - `招待メール送信`（通常運用）  
   - `招待URLをコピー`（メール不達時の代替）  
5. 受け取り側は ` /invite ` 画面で初回パスワード設定を完了します。

## 4. 既存ユーザー編集
1. 対象ユーザー行の `編集` を押します。  
2. 変更内容を入力します。  
   - 表示名  
   - ロール（操作可能範囲内のみ）  
   - USERの場合: 店舗アクセス  
3. `保存` を押して完了です。

## 5. 削除の使い分け（重要）
### A. 組織から外す
- 対象ユーザーの `この組織の所属` だけを外します。
- Authユーザー自体は残るため、同じメールの再招待時は既存アカウント再利用になります。

### B. 完全削除（ADMINのみ）
- Authユーザーを完全削除します（取り消し不可）。
- 2段階確認が表示されます。
- 他組織に所属が残っている場合は削除できません（安全ブロック）。

## 6. 招待URLコピー / 再設定URLコピー
### 招待URLコピー
- 新規作成モーダルで `招待URLをコピー` を押します。
- URLをチャット等で直接共有できます。

### 再設定URLコピー
- 既存ユーザーの `編集` モーダルで `再設定URLをコピー` を押します。
- パスワードを忘れたユーザー向けです。

## 7. よくあるエラーと対処
### `A user with this email address has already been registered`
- 既存Authユーザーです。
- 正常系として `再設定URLコピー` か `招待URLコピー`（既存再利用）を使ってください。

### `otp_expired / Email link is invalid or has expired`
- 招待リンクの期限切れです。
- 管理者側で招待URLを再発行してください。

### `Not allowed / 権限不足`
- ロール権限外の操作です。
- 上位ロール（ADMIN or SUPERVISOR）に依頼してください。

### `planCode is required...`
- 対象orgの初回顧客ユーザー作成時に契約プラン未設定です。
- 先に `契約プラン` 画面でプラン割当を行ってください。

## 8. 運用上の推奨
- まずは `組織から外す` を使い、`完全削除` は最終手段にしてください。
- メール不達時はすぐに `招待URLコピー` を使って運用停止を防いでください。
- 監査用ユーザーは名前に `[AUDIT]` 接頭辞を付け、定期的に整理してください。

## 9. 監査ユーザー再生成ルール（2026-02-16 追加）
- 監査実行前は毎回 `npm run audit:bootstrap:users` を実行します。
- 再生成は以下の順で実施します。
  1. 同メールの既存ユーザーを検索
  2. 見つかった場合は `admin-user-delete`（`FULL_DELETE` 2段階確認）で削除
  3. `admin-create-user` で再作成（`orgId + storeId` 必須）
- これにより、`Invalid login credentials` や古い所属情報の混入を防ぎます。

## 10. 監査系コマンド
- 事前整備: `npm run audit:bootstrap:users`
- API監査（自己修復込み）: `npm run audit:api:user-provisioning`
- フル監査: `npm run audit:full`
