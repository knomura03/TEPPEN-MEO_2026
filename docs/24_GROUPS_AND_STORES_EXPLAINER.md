# グループ・店舗・ユーザーの関係（管理ユニット対応）

最終更新: 2026-02-15

## 1. 用語
- **グループ** = `organizations`（会社/チェーン単位）
- **店舗** = `stores`（運用単位）
- **ユーザー** = `profiles` + `memberships`（権限と所属を持つ人）
- **管理ユニット** = `management_units`（SUPERVISORの管理境界。ADMINのみ可視）

## 2. 構造（現在仕様）
- `1グループ : N店舗`
- `1店舗 : Nユーザー`
- `SUPERVISOR 1人 : 1管理ユニット`
- `1管理ユニット : Nグループ`

## 3. 何をどこで管理するか
### グループ
- 役割: データ分離・権限境界の基準
- 主な操作画面: `グループ管理`
- できること: グループ作成（ADMIN/SUPERVISOR）、名称変更（ADMIN/SUPERVISOR/MANAGER）

### 店舗
- 役割: 投稿・受信箱・SNS連携・指標の運用単位
- 主な操作画面: `店舗管理`、`プラットフォーム管理`、`契約プラン`
- できること: 店舗作成/編集、SNS連携、店舗ごとの契約プラン変更

### ユーザー
- 役割: ログイン主体と担当割当
- 主な操作画面: `ユーザー管理`
- できること: 新規招待、既存ユーザー追加、店舗/グループ参加管理

## 4. 新規作成ルール（重要）
- 新規ユーザー作成時は、**必ずグループと店舗を指定**します。
  - 既存を選ぶ / 新規を作る のどちらでも可
- 既存メールでの「新規招待」は不可です。
  - 既存ユーザーの参加追加は `既存ユーザーを追加` を使います。

## 5. 管理ユニット境界
- ADMIN: 全管理ユニットを管理可能
- SUPERVISOR: 自分に割り当てられた管理ユニット配下のみ管理可能
- MANAGER/USER: 管理ユニット概念は画面非表示

## 6. よくある誤解
### Q. 店舗を複数グループで共有できますか？
- 現仕様ではできません（テナント境界維持のため）。

### Q. 店舗グループ（`store_groups`）は使いますか？
- 現在の運用UIでは使いません（混乱防止のため非表示）。

### Q. 契約プランはグループ単位ですか？
- いいえ。現在は**店舗単位**です。
