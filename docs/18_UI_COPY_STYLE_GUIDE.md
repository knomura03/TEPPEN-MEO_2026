# UI文言スタイルガイド（運用版）

最終更新: 2026-02-10

## 1. 目的
- 画面の言葉を「専門知識がなくても分かる」表現に統一する。
- 同じ意味の文言を、画面ごとに別の言い方にしない。
- 障害対応用の技術語は通常表示から外し、必要時のみ表示する。

## 2. 基本ルール
- 専門用語より、行動が分かる言葉を優先する。
- 英語ラベルは原則使わない（固有名詞を除く）。
- 見出しは「画面名」と「この画面でできること」を一致させる。
- 接続状態や実行結果は、必ず日本語ラベルで表示する。
- 技術詳細（認証方式、モード、エラー詳細など）は折りたたみ表示にする。

## 3. 用語統一（UI表示）
- `統合受信箱` → `受信箱`
- `SLA` → `対応期限`
- `Provider` → `連携先`
- `Current Plan` → `現在の契約プラン`
- `外部運用` → `別システム管理`
- `ユーザー・契約管理` → `ユーザー管理`
- `しきい値` → `口コミ案内の基準点`
- `NAP` / `整合性` → `店舗情報（名前・住所・電話）` / `一致確認`
- `run` → `実行`
- `store単位` → `店舗ごと`
- `auth` / `runtime` → `認証方式` / `動作モード`
- `P3-03` のようなチケット番号 → 通常UIでは非表示（ドキュメントのみ）

## 4. 実装ルール
- 画面ラベルは `components/ui/copy.ts` に集約する。
- 表示変換（ロール、状態、日付）は `components/ui/formatters.ts` を使う。
- 新規画面追加時は、本ファイルの用語表に追記してから実装する。

## 5. 更新フロー
1. 文言案を本ファイルへ追加
2. 画面実装へ反映
3. 主要画面（ダッシュボード、設定、投稿、ユーザー管理）を目視確認
4. 必要なら runbook 文言も合わせて更新
